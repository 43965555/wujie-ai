// 05 — 推理网关架构 · ARCHITECTURE

多活推理网关

按模型路由 + Locality-aware 亲和调度 + 冷热流量分离——这是把 5× QPS 提升落到工程的真正原因。

HOT · 高频实时
WARM · 中频批量
COLD · 长尾弹性
实线 = 同步 虚线 = 异步回环
DECISION 01

为什么三档流量分离？

GPU 成本曲线非线性——长尾冷流量走 Serverless 把单位 token 成本砍掉 68%，同时热路径稳定性不被影响。

DECISION 02

为什么 ID-Hash 而非 Round-Robin？

Prefix Cache 命中率取决于会话粘连性——ID-Hash 让相同会话始终落在同一 vLLM 0.10+ 实例，KV-cache 复用率从 12% 拉到 78%。

DECISION 03

为什么 OTel 全链路 trace？

Token 级审计让单次推理的 prompt / 完成 / cost / latency 全可追溯——这是模型事故 P0 复盘能 1 小时定位的根因。
